# BootLock — собственный загрузчик ОС с игрой и паролем

Лабораторная работа: загрузчик в загрузочном секторе (MBR) жёсткого диска.
При включении компьютера он требует отыграть минуту в Space Invaders, затем
запрашивает пароль, показывает список установленных ОС, делает выбранную
активной и загружает её. Пароль и прочие настройки задаются программой `bootcfg`.

![Space Invaders](docs/2_game.png)

## Последовательность загрузки

| Шаг | Что происходит | Где в коде |
|---|---|---|
| 1 | BIOS загружает MBR (LBA 0) в 0000:7C00 | — |
| 2 | stage1 копирует себя в 0000:0600, читает конфиг (LBA 1), проверяет сигнатуру `BLCF`, читает stage2 | `src/stage1.asm` |
| 3 | Титульный экран, затем Space Invaders в VGA 13h — нужно провести в игре 60 с | `src/game.asm` |
| 4 | Ввод пароля: соль + SHA-256 × 5000, сравнение без раннего выхода | `src/sha256.asm`, `src/stage2.asm` |
| 5 | Меню ОС по таблице разделов MBR (имена из конфига или по типу раздела) | `src/stage2.asm` |
| 6 | Чтение VBR выбранного раздела, проверка 55AA | `chainload` |
| 7 | **Активация**: флаг 0x80 у выбранного раздела, 0 у остальных, MBR записывается на диск | `activate` |
| 8 | Передача управления VBR: `DL` = диск, `DS:SI` → запись раздела (стандартный протокол MBR) | `chainload` |

## Размещение на диске

| LBA | Содержимое |
|---|---|
| 0 | stage1 — 440 байт кода; подпись диска и таблица разделов (байты 440–511) **не трогаются** |
| 1 | конфиг: длительность игры, соль, хеш пароля, число итераций, имена ОС, скрытые разделы |
| 2 | резервная копия исходного MBR (для `bootcfg uninstall`) |
| 3…14 | stage2 (≈5,6 КБ) — в «зазоре» до первого раздела (обычно LBA 2048) |

stage2 помещается даже на старых дисках, где первый раздел начинается с LBA 63.

### Карта памяти (реальный режим)

| Адрес | Назначение |
|---|---|
| 0000:0600 | копия MBR (stage1 + таблица разделов) — отсюда VBR получает `DS:SI` |
| 0000:7C00 | сюда грузится VBR выбранной ОС; ниже — стек |
| 1000:0000 | конфиг; 1000:0200 — бэкап MBR; 1000:0400 — stage2 и его переменные |
| 2000:0000 | задний буфер кадра 320×200 (64 000 байт) |
| A000:0000 | видеопамять VGA |

## Игра

- Захватчики 5×8, три вида с анимацией в два кадра; ускоряются по мере уничтожения.
  После уничтожения всей волны приходит следующая, быстрее и ниже.
- Управление: ←/→ или A/D — движение, Space — выстрел.
- Свой обработчик IRQ1 (INT 9) хранит состояние каждой клавиши — управление
  плавное, без автоповтора BIOS. После игры восстанавливается обработчик BIOS.
- Двойная буферизация: кадр рисуется в 2000:0000 и копируется в A000 через `rep movsd`.
- Шрифт 8×8 берётся из BIOS (`INT 10h AX=1130h`), спрайты сгенерированы из
  ASCII-арта (`tools/gen_data.py`).
- **Пропустить игру нельзя.** На титульном экране работает только Space. Таймер
  считает время только во время игры (паузы после гибели не засчитываются).
  Потеря трёх жизней или прорыв захватчиков — **таймер начинается заново**.
- Время считается по счётчику тиков BIOS (0040:006C, 18,2 Гц).

## Пароль и безопасность

```
h = SHA-256(salt ‖ password)
повторить (N−1) раз:  h = SHA-256(h ‖ salt)        salt — 16 случайных байт, N = 5000
```

- SHA-256 (FIPS 180-4) реализован на ассемблере для 386 в реальном режиме.
  Тест сверяет результат ассемблера с `hashlib` побайтно.
- Пароль на диске не хранится — только соль и хеш. При каждой смене пароля
  генерируется новая соль.
- Сравнение хешей без раннего выхода (без утечки по времени), буфер с паролем
  после проверки затирается.
- После каждой неверной попытки задержка растёт (2, 4, 6… с). После N попыток
  (по умолчанию 3) система блокируется до перезагрузки.

**Модель угроз — что загрузчик НЕ защищает.** Как и любой парольный загрузчик
без шифрования, BootLock защищает только от включения компьютера «в лоб». Его
обходят загрузкой с флешки, снятием диска или правкой MBR из другой ОС.
Хеш с солью и 5000 итерациями замедляет перебор, но слабый пароль всё равно
подбирается офлайн. Для реальной защиты нужны пароль BIOS/UEFI, Secure Boot и
полнодисковое шифрование (BitLocker, LUKS).

## Программа настройки `bootcfg`

```bash
python3 -m bootcfg install /dev/sdX            # установить (спросит пароль дважды)
python3 -m bootcfg install disk.img --game-seconds 60 --iterations 5000
python3 -m bootcfg passwd  disk.img            # сменить пароль
python3 -m bootcfg passwd  disk.img --disable  # отключить пароль
python3 -m bootcfg set disk.img --name 1="Windows 10" --name 2="Ubuntu 24.04"
python3 -m bootcfg set disk.img --hide 4 --default 2 --attempts 5 --game-seconds 30
python3 -m bootcfg show    disk.img            # настройки и разделы
python3 -m bootcfg verify  disk.img            # проверить пароль офлайн
python3 -m bootcfg uninstall disk.img          # вернуть исходный MBR
python3 -m bootcfg mkdemo  demo.img            # демо-диск: 3 «ОС» + раздел без ОС
```

Поддерживаются образы `.img`, `.vhd` (fixed и dynamic — модуль из лабы
`diskimg`) и реальные устройства. Перед установкой `bootcfg` проверяет:

- MBR, а не GPT;
- первый раздел не залезает в нужные загрузчику секторы;
- зазор пуст — там нет, например, GRUB; иначе нужен `--force`.

Таблица разделов сохраняется; при переустановке не теряется самый первый бэкап MBR.

## Сборка и запуск

```bash
sudo apt install nasm qemu-system-x86 imagemagick
make                                         # build/stage1.bin, stage2.bin, demo_os.bin

python3 -m bootcfg mkdemo demo.img
python3 -m bootcfg install demo.img
qemu-system-i386 -drive file=demo.img,format=raw
```

Для VirtualBox или Hyper-V создайте демо-диск как `demo.vhd` и подключите его к
ВМ в режиме BIOS (не EFI).

> **Реальное железо.** Ставьте только на диск с Legacy/BIOS-загрузкой и только
> после резервной копии: `sudo dd if=/dev/sdX of=mbr-backup.bin bs=512 count=2048`.
> Если Linux загружается через GRUB в MBR, после установки BootLock GRUB нужно
> установить в загрузочный сектор раздела (VBR).

## Демо-«ОС»

`demo/demo_os.asm` — загрузочный сектор раздела. Он печатает на экран и в COM1,
какие параметры получил от загрузчика. По этому выводу тесты проверяют
корректность передачи управления:

```
[OS] Booted: Ubuntu 24.04 (demo)
[OS] boot drive (DL) = 0x80
[OS] partition LBA (DS:SI+8) = 0x00008000
[OS] partition flag (DS:SI) = 0x80
```

## Тестирование

18 тестов (`tests/test_bootlock.py`) запускают настоящую загрузку в QEMU.
Клавиатура эмулируется через монитор QEMU (`sendkey`), результат проверяется
по журналу COM1, скриншотам и содержимому диска после загрузки.

| Тест | Что проверяет |
|---|---|
| `test_full_boot` ×2 | полный путь игра → пароль → меню → ОС; DL, DS:SI, LBA; на диске активен ровно выбранный раздел |
| `test_menu_arrows` | навигация стрелками с переходом через край списка |
| `test_hash_asm_equals_python` | SHA-256 × 5000 на ассемблере совпадает с `hashlib` |
| `test_wrong_then_right_password` | неверный пароль, задержка, затем верный |
| `test_backspace_and_escape` | редактирование поля ввода |
| `test_lockout` | блокировка после N попыток, дальнейший ввод игнорируется |
| `test_partition_without_os` | раздел без 55AA: ошибка, возврат в меню, раздел **не** активирован |
| `test_game_cannot_be_skipped` | Esc/Enter не пропускают ни титул, ни игру; отпускает не раньше срока |
| `test_game_over_resets_timer` | без игрока бомбы отнимают жизни → сброс таймера |
| `test_no_game_no_password`, `test_hidden_and_default` | настройки из `bootcfg` действуют |
| `test_vhd_boot` | загрузка с dynamic VHD (`-drive format=vpc`) |
| `test_install_uninstall_roundtrip` | таблица разделов цела, `uninstall` возвращает исходный MBR побайтно |
| `test_install_refuses` | отказ на GPT, на разделе в зазоре, на чужих данных (без `--force`) |
| `test_password_rules`, `test_kdf_vector` | ограничения пароля, пароль не хранится, новая соль при смене |

```bash
python3 -m pytest -v tests/        # ~4 минуты
python3 tests/screenshots.py docs  # переснять скриншоты
```

## Структура проекта

```
src/stage1.asm     MBR: перемещение, LBA-чтение конфига и stage2
src/stage2.asm     главный поток, пароль, меню, активация, chainload, данные
src/game.asm       Space Invaders, графика 13h, обработчик клавиатуры
src/sha256.asm     SHA-256 и проверка пароля
src/util.asm       текстовый режим, рамки, COM1, задержки, ГСЧ
src/config.inc     формат сектора конфигурации (общий с bootcfg)
tools/gen_data.py  генерация констант SHA-256 и спрайтов → src/data.inc
bootcfg/           программа установки и настройки (Python)
demo/demo_os.asm   демонстрационная «ОС»
tests/             QEMU-тесты и снятие скриншотов
```

## Ограничения

- Только BIOS / Legacy-загрузка и MBR. UEFI и GPT не поддерживаются: на UEFI
  код MBR не выполняется вовсе.
- Пароль — печатные ASCII-символы, ввод в US-раскладке (так работает
  клавиатура BIOS). Интерфейс на английском, потому что шрифт BIOS не содержит
  кириллицы.
- В меню показываются 4 основных раздела; логические диски внутри расширенного
  раздела не загружаются (у них нет стандартной загрузки через VBR из MBR).
- Нужен процессор 386+ и BIOS с расширениями INT 13h (любой ПК после ~1998 года).
